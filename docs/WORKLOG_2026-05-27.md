## 1. 背景与目标

为 TTS 大模型的"**指令生成**"场景（用户给参考音频 + instruction → 输出音色相似、风格按 instruction 变化的新音频）构造训练 pair。

**两套上游数据**（本项目只读，不修改）：

- **vcdata** —— `vcdata_construction/`：每条 kxhuang 真实音频 → MOSS-TTS 合成 16 个候选 → 取音色相似度最高的 ref_audio（每 split 10000 条）。本质是"音色保持 + 文本替换"。
- **editx** —— `vcdata_construction/.../split_XXXX/stepaudio_<edit_tag>_split_XXXX_all_qzrun/`：把 ref_audio 喂给 stepfun-editx 跑 6 种 edit 模式，已验证 **style_radio 是最稳的中性化方案**（mean P(neutral)=0.702，BOTH agree 68.6%）。

**6 种 pair 类型**（最终口径）：

| 编号 | 类型 | reference | target | instruction 示例 |
|---|---|---|---|---|
| **A** | 只换文本，表达基本不变 | 真实 original_audio | vcdata ref_audio (同音色不同文本) | "保持参考音色，只换文本"（后标注，可选） |
| **B-clean** | 平淡 → 高表现 | edited_audio (中性化后) | ref_audio (高表现) | "更有感染力 / 更有起伏 / 更像旁白" |
| **C-clean** | 高表现 → 平淡 | ref_audio (高表现) | edited_audio (中性化) | "平静一点 / 不要这么夸张 / 去掉情绪起伏" |
| **H1** | 零变化对照 | original_audio | ref_audio | "保持原样，不要改变表达方式" |
| **H2** | 已满足指令对照 | 已中性 edited_audio | 同 / 同属性近邻 | "更中性 / 去掉情绪起伏" |
| **H3** | 跨 speaker 负样本 | A 中 ref | 跨行 random ref | "（负样本，不应学习）" |

## 4. 中间表设计

### 4.1 vcdata_base.jsonl

```json
{
  "sample_id": "split_0000:000000",
  "split": "split_0000",
  "original_idx": 0,
  "original_audio": "...",
  "original_text": "...",
  "ref_audio": "...",
  "ref_text": "...",
  "speaker_similarity": 0.91,
  "flag": "OK | LOW_SIM",
  "duration": 3.7,
  "caption_summary": "...",
  "caption_gender": "Male",
```

### 4.2 editx_base.jsonl
每行 = editx 的 `paired_report.jsonl` 标准化（所有 edit 模式合并）：

```json
{
  "sample_id": "split_0000:style_radio:000000",
  "split": "split_0000",
  "source_row_index": 0,
  "edit_tag": "style_radio",

  "input_text": "...",
  "edited_audio": "...",

  "original_audio_from_meta": "..."

```

### 4.3 joined_editx.jsonl
`editx_base ⋈ vcdata_base on (split, source_row_index == original_idx)`，每条 editx 记录回填 vcdata 字段。

## 5. emotion 评估

对 3 类音频跑 emotion2vec_plus_large + SenseVoiceSmall：
- `original_audio` 池（kxhuang 真实音频，需 symlink 转 .wav）
- `ref_audio` 池（vcdata 合成）
- `edited_audio` 池（每个 edit_tag 一个目录）

产物：`emotion/per_file_dual.csv`（path → 9 类概率 + top1 + sv_label）。

**`--reuse-qzrun` 模式**：split_0000 直接 symlink emotion_eval 项目已有的 qzrun 结果，但**不含 original_audio 评分**——所以 H1 在此模式下产 0 条，需跑完整 04 才能补。

## 6. 各类 pair 的构建逻辑

### 6.1 A —— 只换文本，表达基本不变

**脚本**：`05_construct_A.py`  
**来源**：`vcdata_base.jsonl` 全量  
**过滤**：仅 `sim_min` 与 `flag` 可选门槛（当前 `sim_min=0`，不筛）

```python
reference = original_audio        # 真实 kxhuang
target    = ref_audio              # MOSS-TTS 合成，同音色不同文本
instruction = "保持参考音色，只换文本，表达方式基本不变"  # 后标注
```

**口径**：A 等价于 vcdata 全量。vcdata 的设计目标就是"音色保持 + 文本替换"，所以不再做二次 emotion 过滤；要更严格的"低表达变化"子集，看 H1。

**产出**：split_0000 = **10000 条**

---

### 6.2 B-clean —— 平淡 → 高表现

**脚本**：`06_construct_B_clean.py`  
**来源**：`joined_editx.jsonl`，仅 `edit_tag ∈ ["style_radio"]`

```python
reference = edited_audio  # 经 style_radio 中性化（平淡）
target    = ref_audio      # 原 vcdata ref（高表现）
text 两边 = ref_text       # 同文本
instruction = 随机选 "更有感染力" / "更有起伏" / "更像旁白"
```

**过滤**（全部满足）：
1. `P_neutral(edited) >= 0.70` — edited 必须足够中性
2. `P_neutral(ref) <= 0.95` — ref 不能是纯播报感

**产出**：split_0000 = **789 条**（ref P(neu)>0.95 的纯平淡 1061 条被丢弃）

---

### 6.3 C-clean —— 高表现 → 平淡

**脚本**：`07_construct_C_clean.py`  
**与 B 对称**，源、过滤完全一致，仅 reference 和 target 互换：

```python
reference = ref_audio      # 原 vcdata ref（高表现）
target    = edited_audio   # 经 style_radio 中性化（平淡）
text 两边 = ref_text
instruction = 随机选 "平静一点" / "不要这么夸张" / "去掉情绪起伏"
```

**这是项目主线**——用户的核心需求是"高表现力音频经指令变中性"。

**产出**：split_0000 = **789 条**

---

### 6.4 H1 —— 零变化对照

**脚本**：`08_construct_H1.py`  
**目的**：让模型学"当 instruction 说『保持原样』时，target ≈ reference"  
**来源**：`vcdata_base.jsonl`

```python
reference = original_audio
target    = ref_audio
instruction = "保持原样，不要改变表达方式"
```

**过滤**（全部满足）：
1. `speaker_similarity >= 0.0`（可选，当前不筛）
2. `emotion(original).top1_label == emotion(ref).top1_label`
3. `cosine9(emotion(original), emotion(ref)) >= 0.97`（9 维情感概率向量极相似）

**关键**：H1 需要对 **original_audio** 也跑 emotion 评分。当前 reuse-qzrun 模式下没评 original，所以 H1 = 0。要跑完整 `04_run_emotion_eval.sh`（约 60~90 分钟 GPU）才能补齐。

**与 A 的关系**：A = vcdata 全量；H1 = A 中表达几乎完全不变的精筛子集，预期几百到一千级别。

---

### 6.5 H2 —— 已满足指令对照

**脚本**：`09_construct_H2.py`  
**目的**：让模型学"当 reference 已满足目标属性时，再叫它去满足同样属性，不应过度增强"  
**来源**：`joined_editx.jsonl`，仅 `edit_tag == style_radio`

```python
reference = edited_audio  # 已经被中性化
target    = edited_audio  # mode=self（自对照），或 mode=neighbor（同属性池近邻）
instruction = 随机选 "更中性" / "去掉情绪起伏" / "更像新闻播报"
```

**reference 候选过滤**（全部满足）：
1. `P_neutral(edited) >= 0.90` — emotion2vec 高置信中性
2. `sv_label(edited) == "neutral"` — SenseVoice 双印证

**两种 target 模式**：
- `mode: self`（默认）：target = reference 自身，最简单无歧义
- `mode: neighbor`：从同属性池里随机取另一条 edited_audio

**当前 editx 只覆盖中性化方向**，所以 H2 实质是"已中性 → 再叫更中性"。未来扩 happy/angry 时可加 source_edit_tag 列表。

**产出**：split_0000 = **1741 条**

---

### 6.6 H3 —— 跨 speaker 负样本

**脚本**：`10_construct_H3.py`  
**目的**：显式负样本，告诉模型"跨 speaker 不该匹配"  
**来源**：`vcdata_base.jsonl`，每个 A anchor 配 1 个负样本

```python
reference = anchor.ref_audio
target    = random_other_row.ref_audio   # 不同 source_row_index
instruction = "（负样本，不应学习）"
is_negative = True
```

**可选强约束**（默认关）：`require_gender_mismatch: true` 要求 caption_gender 不同，更稳的跨 speaker。

**产出**：split_0000 = **10000 条**（每个 A anchor 1 个负样本）

## 7. 阈值校准过程（B/C 的关键决策点）

### 7.1 起点：默认 `ref_neutral_max = 0.50`

第一次跑出 B/C 各 526 条，从 1850 个候选里丢弃 1324 条"ref 太中性"。怀疑这道阈值卡太严，决定看分布 + 听感。

### 7.2 分布发现：双峰

```
ref P(neutral) 分布（style_radio 共 2700 条）：
  [0.0~0.1)    1068 (39.6%)   明显高表现
  [0.1~0.95)   509  (18.8%)   过渡带
  [0.95~1.0]   1123 (41.6%)   明显纯中性
```

**两端集中**，中间稀疏。阈值在 0.6~0.95 之间影响只有 ~280 条；真正的分水岭在 0.95。

### 7.3 听感对照（关键步骤）

抽 7 档共 45 条 ref_audio 让人耳判断：

| 档位 | P(neutral) | 数量 |
|---|---|---|
| low_high_expressive | 0.000 (top1=happy/angry) | 5 |
| mid_borderline | 0.45~0.52 | 5 |
| band_70_85 | 0.70~0.85 | 6 |
| band_85_95 | 0.85~0.95 | 8 |
| band_95 | 0.94~0.96 | 8 |
| band_98 | 0.97~0.985 | 8 |
| high_neutral | >0.98 | 5 |

听完后判断：**0.98 那批仍能听出日常对话语调起伏，不算平淡**。

### 7.4 关键洞察：模型口径 ≠ 人耳听感

现场验证 `001159_ref.wav` (P_neu=0.9789)：
- emotion2vec_plus_large: `neutral` (P=0.9789)
- SenseVoiceSmall: `<|NEUTRAL|>`
- 转写文本: "好啊那你跟右主呢"

**两个分类器都判 neutral，但人耳听感不平淡**。原因：

> emotion2vec 和 SenseVoice 的 "neutral" 类含义是**"不属于 6 大强情感类别（happy/angry/sad/fearful/surprised/disgusted）"**，而不是"声音完全平淡无起伏"。

日常对话、朗读等"自然语调"虽然有语调高低和节奏变化，但因没有强情绪类别，被两个模型判为 neutral。

### 7.5 最终决策：`ref_neutral_max = 0.95`

**理由**：
1. 训练 TTS 让它学"加强/削弱表现力"——自然语调起伏的 ref 是有价值的样本，模型应学会"比这个 ref 更激情"
2. 0.95 仍能挡掉 P>0.95 那 1123 条彻底平淡的纯播报感片段
3. 数据量从 552 → 789（+45%）

## 9. 关键设计决策记录

| 决策 | 理由 |
|---|---|
| **A0 / A 合并为 A** | A 实质就是 vcdata 全量。不再拆"基础底座 / 精筛"两层。 |

### 12.1 入口

```bash
cd /inspire/.../projects/pair_construction
```

`run_e2e.sh` 串联 5 阶段（任何一阶段已完成则跳过，可断点续跑）：

| 阶段 | 调用 | 耗时（100 句） |

### 12.2 demo 产出（100 句）

| pair | rows |
|---|---|
| A | 100 |
| B_clean | 33 |
| C_clean | 33 |

### 12.3 踩的坑（都已沉淀到脚本里）

1. **`activate_emotion_eval.sh` 的 `set -euo pipefail` 会污染 source 它的 shell** → 全改成 exec 模式 `bash activate ... cmd` 或直接用绝对 python 路径
2. **`run_step_editx_split.sh` 顶部用 `python` 命令但 conda activate 在后面** → 传 `PYTHON_BIN=step_audio_editx/bin/python`
3. **系统缺 ffmpeg** 转 flac→wav 失败 → 改用 `soundfile.read/write`
4. **`split_demo` 不是 `split_NNNN` 数字格式** → 02/04 路径解析用 glob `stepaudio_*_{split}_*/paired_report.jsonl`，不再强依赖数字模板
5. **`_links_original/*.wav` 是真实文件不是 symlink，emotion CSV 的 path 跟 vcdata 的 original_audio 真实路径对不上** → 04 转码时同步写 `_mapping.csv (link_wav → original_audio)`，`_emotion_lookup.load_link_mapping` 把 link_wav 的 emotion record 别名注册到 original_audio。这步修复后 H1 / A 的 `ref_emotion` 字段才能正确填充

### 12.4 H1 阈值实验（split_demo 100 句）

| cosine_min | H1 行数 |
|---|---|
| **0.97**（默认） | **46** |
| 0.90 | 47 |
| 0.80 | 50 |
| 0.70 | 51 |

变化极小，因为 `same_top1_label: true` 这道硬过滤已经卡掉 49 条 top1 不一致的样本，剩 51 条几乎都满足 cosine≥0.97（top1 相同时 9 维概率向量本就高度对齐）。

**结论**：H1 默认 0.97 锁定，不再放宽。

## 13.3 跨文本变体：C-mixed

C_clean 是同文本（ref_text == target_text），实际训练场景可能希望 reference 和 target 文本不同。**C-mixed** 通过换 reference 来源实现：

| 字段 | C-clean | C-mixed |
|---|---|---|
| reference_audio | vcdata ref_audio（合成）| **original_audio**（真实） |
| reference_text | ref_text | **original_text** |
| target_audio | edited_audio | edited_audio |
| target_text | ref_text | ref_text |
| 文本关系 | 同 | **不同** |
| speaker | 同（合成 vs 合成）| 同（真实 vs 合成同音色）|
| instruction | "平静一点" | "去掉情绪起伏，**按下面文字平静地说**" |

**实现**：`scripts/07b_construct_C_mixed.py`，配置在 yaml `c_mixed` section，复用 `bc_clean` 的 edited_neutral_min / ref_neutral_max 过滤（但 ref 端查的是 original_audio 的 emotion，不是 ref_audio）。

**split_demo 实测**：C_mixed = 55（vs C_clean = 33）—— 中文上反而多，因为 original 的 P_neutral 分布偏低（真音频更多带情绪），ref_neutral_max≤0.95 这道门更容易过。

**适用场景**：当训练目标是"用户提供任意高表现 ref 音频 + 任意新文本 + instruction → 模型按指令风格生成新文本音频"——C-mixed 更贴近这种推理形态。

## 13.4 qwen-tts 中性化方案调研（结论：当前不可用）

**动机**：有同事记忆中"qwen-tts 克隆任何音频都默认中性化"，若属实可作为 stepfun-editx style_radio 的补充/替代方案。  
**结果**：调研后假设**不成立**，记录如下避免后续重复趟坑。

### 13.4.1 测试 Qwen3-TTS-12Hz-1.7B-Base（10 句 voice clone）

接口：`Qwen3TTSModel.generate_voice_clone(text, language, ref_audio, ref_text)`  
样本：从 split_demo 和 split_demo_en 各取 5 句最高表现力 ref（P_neutral=0.000 的 happy/angry）  
推理 env：`moss_ttsd_sglang` + `pip install qwen-tts`（包内含 modeling 代码）

| 维度 | ref P_neu | **qwen Base 输出 P_neu** | step-editx style_radio P_neu |
|---|---|---|---|
| 10 句平均 | 0.000 | **0.003**（≈ ref，没中性化） | 0.039 |
| 中文 5 句 top1 | happy/angry | qwen 输出仍 angry/surprised | 部分被拉到 neutral |
| 英文 5 句 top1 | happy/angry | qwen 输出仍 angry/happy | 部分被拉到 neutral |

**Base 模型行为定性**："only clones the voice as it is" —— 高保真克隆，**保留 ref 原情绪**，不做中性化。GitHub Discussion #231 也证实 Base 不响应 emotion instruction。

附带 bug：英文短句易触发 "停不下来" — `en_000001` (target="I'm getting so hot too.") 输出 **655 秒**废音频，`en_000051` (target="Ow! Ow! Ow!") 输出 30 秒。可能要装 flash-attn 或限 max_new_tokens 才稳定。

### 13.4.2 测试 Qwen3-TTS-12Hz-1.7B-CustomVoice（3 句默认中性）

接口：`generate_custom_voice(text, language, speaker, instruct=None)`  
关键差异：**不接 ref_audio**，只能从 9 个预设音色（Vivian 等）选；当 instruct 省略时"理论上"默认中性。

| wav | text | CustomVoice (Vivian, 无 instruct) P_neu | top1 | sv |
|---|---|---|---|---|
| zh_044 | "要剿灭国民党的特务斗争手法呢。" | **1.000** ✅ | neutral | neutral |
| zh_056 | "那有什么关系呢？反正他早就恨死我了。" | **0.000** ❌ | surprised | angry |
| en_048 | "What is it?" | **0.000** ❌ | angry | emo_unknown |

**CustomVoice 行为定性**：默认中性只在**中性语义文本**下成立。文本本身带情绪（"恨死我了"）或情绪标点（?!）时仍会跟着文本情感走。

### 13.4.3 全部 4 个 qwen-tts 变体对比

| 变体 | 接 ref_audio | 默认输出 | 支持 instruction | 对项目可用？ |
|---|---|---|---|---|
| **Base** | ✅ | 保留 ref 原情绪 | ❌ | ❌ 不是中性化 |
| **CustomVoice** | ❌ 只能 9 预设音色 | 中性语义文本下默认中性 | ✅ | ❌ 丢失 vcdata 音色 |
| **VoiceDesign** | ❌ 文本描述生成新音色 | 同 CustomVoice 思路 | ✅ | ❌ 不接 ref |
| **VoiceEditing-25Hz**（未发布） | ✅ | TBD | ✅ 可编辑情绪 | ⏳ 等发布再测 |

### 13.4.4 结论 + 给项目的影响

1. **qwen-tts 当前没有任何变体能做"高表现 ref → 中性 target"克隆**。同事的"默认中性"记忆是把 CustomVoice 的"默认中性预设音色 TTS"与 Base 的"voice clone"混了。
2. C/C-mixed 类的生产路径**继续锁定 stepfun-editx**（中文 style_radio / 英文 style_chat），不接入 qwen-tts。
3. 待 `Qwen3-TTS-25Hz-1.7B-VoiceEditing` 发布后值得重测 —— 它是唯一计划支持"克隆 + 情感编辑"的变体。

## 13.5 D 类阈值定型（2026-05-29）

split_demo 在原配置下产出 D=22 句，听完 22 段音频发现 #16 / #21 / #22 三句 ref+tgt 都是 emotion2vec top1=neutral（但 P_neutral 在 0.75~0.95 之间，没踩 `ref_neutral_max=0.95` / `tgt_neutral_max=0.95` 软兜底）。这违反 D 类"双高表现"语义，但软阈值不足以拦截。

**定型方案：加两条硬条件**

```yaml
d:
  cosine_min: 0.95
  same_top1_label: true
  ref_top1_not_neutral: true   # 新：ref top1 不能是 neutral
  tgt_top1_not_neutral: true   # 新：tgt top1 不能是 neutral（与 same_top1 联动）
  ref_neutral_max: 0.95        # 保留作为软兜底
  tgt_neutral_max: 0.95
```

`07c_construct_D.py` 在 `same_top1_label` 检查后增加两条 `top1==neutral` 砍掉逻辑（顺序：缺 emotion → top1 不一致 → ref top1=neu → tgt top1=neu → cos<0.95 → P_neu 软兜底）。

**split_demo 结果对比**

| 维度 | 旧 (n=22) | 新 (n=19) |
|------|-----------|-----------|
| 砍掉的 ref-top1=neu | — | **3 句**（vcdata 全集层面拦 30 句，与已有过滤叠加只剩 3 句净影响）|
| 砍掉的 tgt-top1=neu | — | **0 句**（`same_top1=true` 已让 ref 主导）|

**被砍的 3 句**（编号沿用 `worklog_samples/D_full/`）

| NN | ref top1/P_neu | tgt top1/P_neu | reference_text |
|----|----------------|----------------|----------------|
| #16 | neutral / 0.918 | neutral / 0.923 | 宝贝，关系我已经打通好了，你就等着跟我一起论实。 |
| #21 | neutral / 0.908 | neutral / 0.947 | 好人，你是大海，这是您的福报。 |
| #22 | neutral / 0.748 | neutral / 0.886 | 我是不是得癌症了，我还能活多久啊？ |

听感与 emotion2vec 一致，三句确实偏中性，砍掉合理。

**阈值含义易混点**

`ref_neutral_max=0.95` 是"**允许的最大中性度**"，越**小**越严格（要求 P_neutral 必须 ≤ 阈值才保留）。当前留 0.95 = 几乎不过滤、只兜底；硬切由 `top1_not_neutral` 承担。如果未来要进一步收紧高表现样本，调小 max 即可（如 0.5 → 强制 P_neu ≤ 0.5）。

**产物归档**

- 阈值持久化：`configs/default.yaml` + `configs/default_en.yaml` 同步加两条硬条件
- 脚本：`scripts/07c_construct_D.py` 更新过滤顺序 + stat 输出

## 13.6 D_st 类——高表现→高表现 同情绪同文本（2026-05-29）

D 类是跨文本的，但训练里另有一类同样有价值的信号：「reference 是高表现，target 也是高表现且**同文本**」，对应 voice/style conversion 任务（保情绪、换声学风格）。

**物理可行性**

`joined_editx.jsonl` 里同文本的 audio pair 只能是 `(ref_audio, edited_audio[某tag])`，因为 `edited_audio` 是 stepfun-editx 用 `ref_audio` 改造的，文本不变（都是 `ref_text`）。

要让两者「同情绪 + 双高表现」，就是筛 stepfun-editx 没能改变情绪的样本——editx 大多数情况会改风格/情绪，所以这是「editx 失效子集」，量本来就少。

**脚本：`scripts/07d_construct_D_st.py`**

输出 `D_st.jsonl`，pair_type=`D-st`。过滤顺序与 D 类对称：

```yaml
d_st:
  cosine_min: 0.95
  same_top1_label: true
  ref_top1_not_neutral: true
  tgt_top1_not_neutral: true
  ref_neutral_max: 0.95     # 软兜底
  tgt_neutral_max: 0.95
```

`reference = ref_audio`（MOSS-TTS 合成），`target = edited_audio`（stepfun-editx 改造），方向与 D 保持一致（"合成参考 → 受控目标"）。

**split_demo 实跑结果**

```
D_st = 10  (top1≠ 39, ref-top1=neu 50, tgt-top1=neu 0, cos< 1, ref/tgt 太中性 0, 缺emotion 0)
```

100 个 `(ref, edited)` 候选 → 10 句通过：
- **50 句**因 ref_audio 本身 top1=neutral 被砍（MOSS-TTS 16 候选 argmax 没卡情绪，约一半 ref 偏中性，这也解释了 D 类 22→19 的 3 句来源）
- **39 句**因 editx 改了 top1 被砍（editx 主要功能）
- **0 句**tgt-top1=neutral 单独砍（`same_top1=true` 已让 ref 主导）
- **1 句**top1 一致但 9 维向量分布差异大被 cos<0.95 砍

**画像**

| 维度 | 分布 |
|------|------|
| ref top1 | angry × 4 / surprised × 3 / happy × 2 / sad × 1 |
| source_edit | style_radio × 10（split_demo 只有这一个 tag） |
| 9D cosine | 全部 ≥ 0.986 |
| P_neutral 双边 | 全部 ≤ 0.011（极强表现） |

**与 D 类的语义对比**

| 维度 | D | D_st |
|------|---|------|
| reference | ref_audio (MOSS-TTS) | ref_audio (MOSS-TTS) |
| target | original_audio (真人) | edited_audio (editx) |
| 文本关系 | 跨文本 | **同文本** |
| split_demo n | 19 | 10 |
| 训练信号 | "用同情绪说新内容" | "保情绪换声学风格" |
| target 性质 | 真人参考样（金标准） | editx 漏改情绪样（合成） |

**当前限制**

- split_demo 是 head 100 句 reuse-qzrun 模式，只跑了 `style_radio` 一个 tag，其他 5 tag（`style_remove / style_news / style_chat / emotion_coldness / emotion_remove`）暂无 editx 产物，D_st 量上限被压缩到 100 候选
- 真实生产 split（每 split 10000 句 × 6 tag）走 `submit_editx_batch_h200.sh` 后，D_st 量级会扩展到数千~万级，每个 edit_tag 的"漏改率"也是可分析的副产品

## 13.7 03_join key bug 修复 + 英文 12 句之谜根因（2026-05-29）

发现 split_demo_en (100 vcdata base) 的 `joined_editx.jsonl` 只有 72 行（12 句 × 6 tag），所以 B/C/D_st/H2 量级远低于中文。表面像是英文 editx 处理失败，实际是 **`03_join_editx_with_vcdata.py` 用错了 join key**。

**症状定位**

`editx_base.jsonl` 行数 = 600（100 句 × 6 tag）→ editx 完全成功
`vcdata_base.jsonl` 行数 = 100（100 句完整）
`joined_editx.jsonl` 行数 = 72（仅命中 12 句 × 6 tag）

**根因**

03 旧版用 `editx.source_row_index ⋈ vcdata.original_idx` 做 join，但这两个字段语义完全不同：

| 字段 | 来源 | 语义 | split_demo_en 取值 |
|------|------|------|---------------------|
| `vcdata.original_idx` | 上游 vcdata 输入 jsonl 行号 | 原始 jsonl 中的稀疏行索引 | `[0,1,2,3,48,49,50,51,96,97,98,99,...,1442]` |
| `editx.source_row_index` | editx 输入文件列表序号 | editx 自己的 0~99 连续顺序 | `[0,1,2,...,99]` |

两个集合的交集恰好是 12 个：`{0,1,2,3,48,49,50,51,96,97,98,99}`——这就是「英文只有 12 句产出 join」的真相。

**为什么 split_demo (zh) 没暴露**

split_demo 是 head 100 句 toy demo，vcdata 直接取前 100 行，`original_idx == 0~99` 顺序连号，恰好与 editx 的 `source_row_index` 0~99 对齐，巧合命中 100/100。这个 bug 在 toy demo 上完全无症状。

**未来真实生产 split (split_0001~split_0034) 必然受影响**——因为生产数据集都做了 caption_emotion 筛选，`original_idx` 必然稀疏。

**修复：用绝对路径做 key**

`editx.input_audio` 就是 vcdata 产出的 `ref_audio` 路径，两者天然一一对应，是真正语义级 key：

```python
# 03_join_editx_with_vcdata.py 修复后
vc_index = {r["ref_audio"]: r for r in iter_jsonl(vc_path)}
v = vc_index.get(e["input_audio"])
```

英文 B/C 从 7 → 39，与中文 split_demo 的 33 持平，符合 100 vcdata base 的合理量级。

## 13.8 ref↔tgt speaker_sim 过滤（2026-05-29）

用户听 C 类样本反馈"ref 和 tgt 音色不太像"。用 CAM++ ECAPA-TDNN 全量算 5 类 ref↔tgt cosine，结果：

| pair_type | zh mean | en mean | 物理含义 |
|-----------|---------|---------|---------|
| B (= C 对称) | 0.833 | 0.655 | (ref_audio, edited_audio) 同源派生 |
| C_mixed | 0.563 | 0.368 | (original_audio, edited_audio) 真人↔合成 |
| D | 0.665 | 0.513 | (ref_audio, original_audio) 合成↔真人 |
| D_st | 0.847 | 0.692 | (ref_audio, edited_audio) 同源派生 + 同情绪 |

**两组本质不同**：
- **同管道 (B/C/D_st)**：reference 和 target 都从同一个 ref_audio 派生，sim 偏低就是 editx 改坏了 → 应砍
- **跨管道 (C_mixed/D)**：reference 或 target 是真人 original_audio，sim 偏低是 vcdata MOSS-TTS clone 的物理上限 → 砍掉只会消除"跨管道泛化"训练信号本身

**定型方案**：
- `bc.speaker_sim_min: 0.80` (zh) / `0.70` (en) → 应用于 B + C（同 vcdata 源派生）
- `d_st.speaker_sim_min: 0.80` (zh) / `0.70` (en) → 应用于 D_st
- C_mixed / D 不卡，但写 sim 字段到 jsonl 供训练时按需加权或后期筛选

**脚本**：`scripts/11_add_speaker_sim.py` —— 优先复用 `quality/all_class_ref_vs_tgt_sim.csv` 缓存；对 B/C/D_st 产出 `_filtered.jsonl`，对所有 5 类原 jsonl in-place 加 `ref_vs_tgt_speaker_sim` 字段。

## 13.9 B/C/C_mixed 对称 top1 硬条件（2026-05-29）

用户听 C_mixed 样本发现 ref top1=neutral/P_neu=0.6 的样本被当作"高表现"了。系统扫所有类 reference/target 的 top1=neutral 占比，确认 B/C/C_mixed 都缺顶层硬条件。

**扫到的漏洞**（修前）：

| 类 | 维度 | zh top1=neu | en top1=neu | 漏洞性质 |
|----|------|------------|------------|----------|
| B | target (ref_audio, 应高表现) | 5/33 | 7/39 | 高表现侧漏 |
| B | reference (edited, 应中性) | 33/33 ✓ | 28/39 | en 中性侧 P_neu∈[0.30,0.50] 边缘漏 |
| C | reference (ref_audio, 应高表现) | 5/33 | 7/39 | 高表现侧漏 |
| C | target (edited, 应中性) | 33/33 ✓ | 28/39 | 同 B en |
| C_mixed | reference (original, 应高表现真人) | 12/55 | 6/38 | 高表现侧漏 |
| C_mixed | target (edited, 应中性) | 55/55 ✓ | 27/38 | 同 B en |
| D / D_st | 已修 | 0 | 0 | ✓（§13.5） |

**加的 3 条硬条件**（写入 yaml）：

```yaml
bc:
  ref_top1_not_neutral: true        # 应用于 B 的 target 与 C 的 reference（同 ref_audio）
  edited_top1_must_be_neutral: true # 应用于 B 的 reference / C 的 target / C_mixed 的 target

c_mixed:
  original_top1_not_neutral: true   # 应用于 C_mixed 的 reference（real human）
```

`06/07/07b` 三脚本同步加过滤分支，统计字段加 `cnt_*_top1_neu`。

**修前后留存（split_demo / split_demo_en）**：

| 类 | zh 修前 | zh 修后 | en 修前 | en 修后 |
|----|--------|--------|---------|--------|
| B | 33 | 28 (-5) | 39 | 28 (-11) |
| C | 33 | 28 (-5) | 39 | 28 (-11) |
| C_mixed | 55 | 43 (-12) | 38 | 27 (-11) |

zh 中性侧本来就全过 neutral（阈值 0.70 严），所以 zh 只减 ref 侧；en 阈值 0.30 宽松，两侧都减。

**叠加 §13.8 sim 过滤后的最终数字**：

| | zh top1+sim 后 | en top1+sim 后 |
|--|---------------|---------------|
| B | **22** (/100) | **9** (/100) |
| C | **22** | **9** |
| C_mixed | 43 | 27 |
| D | 19 | 23 |
| D_st | 10 | 9 |

**对英文的根本启示**：100 句 vcdata 经过 top1 双侧硬条件 + sim ≥ 0.70 后只剩 9 句干净 B/C pair，说明英文 stepfun-editx 的中性化与音色保留双弱，未来真实生产 split 量级（每 split 10000 句）下 en B/C 类预期 ~900 句，依旧远低于中文。要么换 baseline，要么扩 vcdata 英文池。
