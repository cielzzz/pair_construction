# pair_construction 阶段汇报与下一阶段计划

> 整理日期：2026-05-29
> 范围：从 vcdata 上游产出到 pair_construction 9 类训练对的完整管线，及下周规模化 B 类（平静→有情绪）的工作分解

## 1. 项目背景

### 1.1 源数据本质

数据组从网上爬取：**视频→去BGM→降噪→响度规整→说话人分类→双ASR交叉验证**。**非录音棚高质量音库**，所有下游指标（DNSMOS / speaker_sim / WER）有先天上限——这点是后续所有阈值/留存率讨论的前提。

### 1.2 完整管线

```
[爬取 jsonl] (上游数据组)
   │
   ▼
vcdata_construction
  - MOSS-TTS 16 候选 voice clone (用同 speaker 别条作 prompt)
  - argmax(speaker_similarity) 选 ref_audio
  - 输出：original_audio, ref_audio (text=ref_text), speaker_similarity
   │
   ▼
vc_edit (stepfun-editx)
  - 用 ref_audio 作 input，按 edit_tag 改造（zh 收敛到 style_radio）
  - 输出：edited_audio (text=ref_text 不变)
   │
   ▼
pair_construction
  - 04 emotion_eval：emotion2vec_plus_large + SenseVoiceSmall + DNSMOS_v4
  - 03 join (路径匹配，修过 bug)
  - 05~10 构造 A / B / C / C_mixed / D / D_st / H1 / H2 / H3 共 9 类
  - 11_add_speaker_sim：WavLM-Large + ECAPA-TDNN (SeedTTSEval) 过滤
```

## 4. 下一阶段工作（按 PM 对话拆解）

### 优先级 1（最高）：规模化 B 类（平静语气 → 有情绪）

> PM 原话：「下周主要的工作就是规模化的造一批从平静语气到有情绪的数据，我们再训几个专家模型看看效果」

**目标**：拿到一批 reference=中性、target=高表现 的 pair 用来训第一版 expressive TTS 专家模型。

**子任务**：

1. **跑 split_0001~split_0034 全量**（34 × 10000 = 340000 句）
   - 资源估算：每 split editx + emotion eval + pair_construction ≈ 4~6 H100·h，总计 ≈ 150~200 H100·h
   - 预期 B 类总产出：**~30000~40000 条**（按 split_demo 10% 留存率）
   - 提交脚本已就绪：`runs/run_zh_full.sh` + `submit_editx_batch_h200.sh`

2. **情绪平衡采样**
   - 现状：B 类 tgt 分布偏 happy/sad/angry，fearful/disgusted < 1%
   - 行动：跑完全量后按 tgt top1 分桶采样，弱情绪类型保留 100%，强情绪类型按需下采样
   - 输出：`B_balanced.jsonl`

3. **统计各情绪比例 + 训练样本数量** —— PM 明确要求
   - 按 (target_top1, ref_speaker_gender) 二维交叉统计
   - 与 caption_tone（一旦标好）联合维度

---

### 优先级 2：多推几遍提相似度

> PM 原话：「可以多推几遍看看能不能随机到」

**问题**：当前同一 (ref_audio, edit_tag) 只跑 1 次 editx，sim 不行就丢了。可以同 input 跑多次取最优。

**实现路径**：

1. editx 接 `--n_attempts 3` 参数（如果上游支持），每次用不同 seed
2. 对同一 ref_audio 收集 N 个 candidates → 算各自 WavLM-L sim → 取最高
3. 预估 sim 留存率从 36% → 50~60%（按 zh B WavLM-L 分布 P25=0.696, P75=0.779 估算）
4. 成本：editx GPU 时间 × N（N=3 大约 +200% GPU）

**实施步骤**：
- 先在 split_demo 100 句小规模测：N=3 的 sim 提升曲线
- 决定是否值得 N=3 全量跑

### 优先级 4：caption 批量标注

> PM 原话：「我们后面批量进行 caption 标注总能标出来的」

**现状**：
- split_0000 的 `caption_emotion` / `caption_tone` 全 None（10000 句都缺）
- 当前 pair_id 的训练 instruction 是 hand-crafted instruction_pool（"用平静的语气朗读"等），缺乏多样性

**目标**：
- 给每条 (ref_audio, tgt_audio) 标 emotion / tone / style 文本描述
- 训练时用 caption 作为 instruction 输入（vs 当前 instruction_pool 模板）

**实施路径**：
1. 选 caption 模型（Audio-LLM：Qwen2-Audio / AudioSetCaps / Gemini Multimodal 等）
2. 批量推理：先 split_demo 100 句试，再 split_0000 10000 句
3. 输出字段加入 pair jsonl：`caption_emotion`, `caption_tone`, `caption_style`

### 优先级 6：多样性扩展

> PM 原话：「还要考虑一些多样性，比如说时长多样性、语言多样性之类的」

**当前现状**：

|------|---------------|------|

**行动建议**：

3. **speaker**：按 gender 下采样平衡（先 50/50）
4. **情绪**：fearful/disgusted 单独收集源数据（影视剧"惊悚/恐怖"类素材）
